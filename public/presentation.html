Кейс проекта

Форма приёма резюме «ПроКадры»

Сайт кадрового агентства: кандидат вставляет резюме текстом, сервис извлекает 7 полей (ИИ GigaChat с эвристическим фолбэком) и ведёт защищённую токеном базу кандидатов на сервере — с поиском, редактированием и экспортом

Задача и контекст

Задача

Принимать резюме произвольного формата (headhunter, текст из письма, «стена» из разделов) и превращать их в структурированную карточку кандидата — без ручного переноса полей.

Целевая аудитория

Рекрутёры кадрового агентства, обрабатывающие поток резюме, и сами кандидаты, которые отправляют резюме через сайт.

Проблема

Резюме приходят сплошным текстом в десятках разных оформлений: зарплата прилипает к соседнему разделу, навыки прячутся под «Профессиональными качествами», контакты — в шапке. Ручной разбор долгий и с ошибками.

Решение

Решение

Одностраничное приложение: форма отправки → извлечение полей через GigaChat API с автоматическим фолбэком на эвристику → карточка кандидата в общей базе на Express-сервере.

Основные функции

7 полей: имя, желаемая должность, зарплата, навыки, опыт, образование, контакты. Добавление, редактирование и удаление; поиск по всей базе; экспорт в JSON и CSV; работа без ИИ (эвристика) и с ИИ (GigaChat).

Использованные инструменты

Node.js и Express; GigaChat API (OAuth + chat completions, сертификаты НУЦ Минцифры); эвристический парсер на чистом JavaScript; хранилище candidates.json с атомарной записью; Bearer-аутентификация и rate limit; автотесты: 107 в npm test (79 эвристика + 28 API) плюс 67 отдельных UI- и security-проверок; OpenCode для разработки.

Безопасность и качество

Доступ к данным

База, поиск и экспорт — только по токену (Bearer, сравнение через timingSafeEqual, без токена — 401); сервер слушает 127.0.0.1. Публична только форма приёма — под rate limit 10 запросов/мин (429).

Защита ввода-вывода

CSV-инъекция обезврежена (префикс апострофа для ячеек =+-@), весь текст рендерится через textContent — XSS не найден; лимиты: 60 000 символов на резюме, 4000 на поле.

Отказоустойчивость

При недоступном ИИ — автоматический фолбэк на эвристику; при недоступном сервере — работа от localStorage с предупреждением о ПДн и кнопкой очистки. Ошибки GigaChat наружу обобщены (детали — только в лог).

Аудит релиза

Read-only аудит нашёл 15 проблем — исправлено 12, включая критическую утечку ПДн без авторизации. Итоговое решение: «готов к учебной публикации». npm audit — 0 уязвимостей.

Результат

Рабочий сервис: кандидат отправляет резюме — рекрутёр через секунду видит структурированную карточку и правит её прямо на странице. Публична только форма приёма; список, поиск и экспорт открываются по токену. При недоступном ИИ форма продолжает работать на эвристике. Финальный аудит: 15 проблем → 12 исправлено (все критические, высокие и средние). Автоприёмка в npm test: 107 проверок.

Скриншоты интерфейса приложения; данные кандидатов — демонстрационные.
