## Положительные находки

1. Секрет `GIGACHAT_AUTH_KEY` живёт только на сервере, клиенту уходит лишь булев `ai` из `/api/health`; в документации и `PROMPT_EXAMPLE.md` — плейсхолдеры, не реальные ключи.
2. `.gitignore` закрывает `.env`, `candidates.json`, `candidates.json.tmp`, `.temp/`, `node_modules/`, бинарные файлы.
3. Безопасный вывод: весь пользовательский текст рендерится через `textContent` / `createTextNode` / `.value`; единственный `innerHTML` — очистка списка (`script.js:593`). XSS не найден.
4. Лимиты ввода: JSON-body 600кб, текст резюме ≤60 000, поля structured ≤4000 — защита от OOM и раздувания базы.
5. Целостность базы: атомарная запись `tmp` + `rename` (`server.js:243–247`), загрузка с фильтрацией мусорных записей.
6. Надёжные исходящие вызовы: таймаут 60с, retry 401 с re-auth, обработка `finish_reason=blacklist`, явный корневой сертификат НУЦ Минцифры + `tls.rootCertificates`.
7. Статика по белому списку файлов, 404-фолбэк, корректные MIME-типы — path traversal и directory listing исключены.
8. Малая CSRF-поверхность: CORS не настроен, JSON-POST не является «simple request» — браузерные cross-site атаки на API не проходят.
9. `npm audit` — 0 уязвимостей (critical/high/moderate/low/info = 0); `package-lock.json` на месте; зависимости сведены к `express` + `dotenv` (+ `playwright-core` dev).
10. Автотесты: `npm test` = 86 кейсов эвристики + 18 API-кейсов (изолированный сервер, прод-база не трогается); `node --check` и регресс описаны в памятке; в `КОМАНДЫ_СЕРВЕР.md` есть раздел «Безопасность».
11. Презентация `case/presentation.html` самодостаточна (всё inline/base64) — открывается по `file://` без сервера и внешних запросов.

## Известные ограничения

- Содержимое `.env` агентом не читалось (запрет правилами) — значение `APP_TOKEN` и ключ GigaChat известны только владельцу; `.env.example2` верифицирован 15.10.2026 (плейсхолдеры, секретов в git-истории нет).
- Низкие риски (строки 13–15 таблицы) закрыты 16.10.2026: бейдж честно переключается на localStorage при HTTP ≠ 2xx; добавлены security-заголовки (helmet), условный HSTS, строгий CSP (кроме `/presentation`), ограничение длины `q` (200 символов → 400) и CI-workflow; эвристика вынесена в `heuristics.js` — тесты подключают её через `require()` вместо `eval`-маркеров.
- Токен передаётся через `?token=` в URL (удаляется из адресной строки сразу же, `script.js:6–20`) — при публичном доступе пользоваться кнопкой «Ввести токен», чтобы URL не попал в историю/логи.
- Рабочие изменения по аудиту закоммичены (`a454c18`, 16.10.2026); изменения доработки 16.10.2026 (строки 13–15, TLS/CI/заголовки) коммитятся отдельно по запросу владельца.
- Не выполнялись: нагрузочный тест, пентест извне, юридическая оценка соответствия 152-ФЗ.
- Режим без TLS приемлем только на `localhost`; публичный контур требует TLS. В коде добавлена опциональная поддержка нативного TLS (`TLS_CERT_FILE`/`TLS_KEY_FILE`) и условный HSTS; выпуск/продление сертификатов и reverse-proxy (Caddy/nginx) — инфраструктура владельца, описана в `Documents/ПРОМЫШЛЕННАЯ.md`.
- `localStorage`-режим — осознанный офлайн-фолбэк, а не отказ от серверного хранения (закрыт предупреждением и кнопкой очистки, строка 8).
- GitHub-ссылка в презентации — заглушка до публикации репозитория.
- Фактическое время ответа GigaChat и поведение при сетевых сбоях в реальной эксплуатации не измерялись.

Замечания (не дефекты, к сведению контура):

- `X-Forwarded-Proto` подделывается любым клиентом, напрямую обращающимся к `127.0.0.1:3000`; эксплуатация невозможна — HSTS поверх чистого http браузерами игнорируется. За reverse-proxy доверять заголовку безопасно (прокси перезаписывает его).
- HSTS включает `includeSubDomains` — при публикации на поддомене это учтёт все поддомены домена.
- `/presentation` теперь закрыт `X-Frame-Options: DENY` (раньше заголовков не было — встраивание было возможно); это ужесточение, презентация открывается только прямой ссылкой.
- CI-workflow составлен и синтаксически выверен, но фактический запуск произойдёт только после push репозитория на GitHub; запуск `npm test` требует `APP_TOKEN` в env (в workflow задан).
- Тест TLS выполнен самоподписанным сертификатом; сертификат от доверенного CA и продление — инфраструктура владельца (`Documents/ПРОМЫШЛЕННАЯ.md`).
